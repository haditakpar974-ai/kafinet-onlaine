# کافی‌نت آنلاین

نسخه ارتقایافته با حفظ طراحی اصلی و افزودن ثبت‌نام، ورود، ثبت سفارش، کد رهگیری، سوابق کاربر و پنل مدیریت.

## امکانات
- ساخت حساب و ورود با ایمیل و رمز عبور از طریق Supabase Auth
- ثبت سفارش فقط برای کاربر واردشده
- ساخت کد رهگیری یکتا برای هر سفارش
- نمایش سوابق سفارش‌های هر کاربر
- پنل مدیریت برای مشاهده همه سفارش‌ها و تغییر وضعیت
- سیاست‌های امنیتی RLS در پایگاه داده؛ نقش مدیر از `app_metadata` خوانده می‌شود

## راه‌اندازی الزامی (سایت بدون این مراحل هنوز به دیتابیس وصل نیست)

### ۱) ساخت پروژه Supabase
1. در وب‌سایت Supabase یک پروژه جدید بسازید.
2. از بخش **SQL Editor** فایل `supabase/schema.sql` را کامل اجرا کنید.
3. از **Project Settings → API** مقدار **Project URL** و کلید عمومی **anon / publishable** را بردارید.
4. فایل `supabase-config.js` را باز کنید و دو مقدار را جایگزین کنید:
   - `YOUR-PROJECT` با شناسه/آدرس پروژه
   - `YOUR_SUPABASE_ANON_OR_PUBLISHABLE_KEY` با کلید عمومی پروژه
5. فایل‌ها را در مخزن GitHub جایگزین کنید و Commit کنید. هرگز `service_role` یا کلید محرمانه را در فایل‌های سایت قرار ندهید.

### ۲) تنظیم تأیید ایمیل
در Supabase → Authentication → URL Configuration، آدرس سایت GitHub Pages را در **Site URL** و مسیرهای برگشت مجاز وارد کنید. برای تست می‌توانید تأیید ایمیل را روشن نگه دارید؛ کاربر باید لینک ایمیل را باز کند.

### ۳) مدیر کردن حساب خودتان
1. ابتدا از فرم سایت با ایمیل خود حساب بسازید و یک بار وارد شوید.
2. در Supabase → Authentication → Users، کاربر خودتان را پیدا کنید.
3. از بخش ویرایش کاربر، مقدار **App Metadata** را به شکل زیر تنظیم کنید (اگر فیلد موجود است):

```json
{"role":"admin"}
```

4. ذخیره کنید، سپس در سایت خارج شوید و دوباره وارد شوید تا توکن جدید دریافت شود.

نقش مدیر را فقط از App Metadata تنظیم کنید؛ هرگز از User Metadata یا ورودی فرم سایت برای اعطای نقش استفاده نکنید.

## نکات امنیتی و حریم خصوصی
- فقط کلید عمومی Supabase در `supabase-config.js` قرار می‌گیرد. کلید `service_role` را هرگز در GitHub یا مرورگر منتشر نکنید.
- اطلاعات تماس و جزئیات سفارش فقط برای کاربر صاحب سفارش و مدیر قابل خواندن است.
- رمز عبور در این سایت ذخیره نمی‌شود و توسط Supabase Auth مدیریت می‌شود.
- کاربران نباید رمز سامانه‌های دولتی، رمز بانکی، کد یک‌بارمصرف یا تصویر مدارک حساس را در توضیحات سفارش وارد کنند.
- این نسخه پرداخت آنلاین ندارد. برای پرداخت واقعی باید درگاه پرداخت معتبر و یک سرور امن سمت‌سرور اضافه شود؛ کلید درگاه را در JavaScript عمومی قرار ندهید.
- برای استفاده عملی، سیاست حفظ اطلاعات، رضایت کاربر، پشتیبان‌گیری و راه ارتباطی پشتیبانی را مشخص کنید.

## انتشار در GitHub Pages
محتویات این پوشه را در ریشه مخزن GitHub قرار دهید و Commit کنید. در Settings → Pages، شاخه `main` و پوشه `/root` را انتخاب کنید.
